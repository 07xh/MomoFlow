# MomoFlow 0.6.0 · 原生页面重构及授权状态修复

## 原因

旧版 `MainActivity` 把账号设置、学习、前台核验、Cortex 与流体云全塞进一条 ScrollView，带来大量说明文字、按钮挤压和长距离滚动。旧 UI 又把「凭证已加密保存」当成「已授权」，遇到 HTTP 403 也不更新连接状态。

## 四页信息架构

- **学习（默认）**：今日真实进度、同步、单词/释义、本机三态练习；缺少开放 API 授权时提供到「连接」快捷入口。
- **流体云**：置顶会话启动/停止；单次前台反馈开关、无障碍设置；高级兼容与诊断默认折叠。
- **核验**：原 App 同词操作前官方基线、返回后回读、三态事务记录；识别及诊断默认收起。
- **连接**：官方开放 API / 独立 Cortex 分区；Cortex 默认 Bearer，备用 Legacy 交换折叠。

原来的长期默认 Home 大卡片、复用工具按钮未删除；本次只做信息归类、样式复用和授权状态纠错。组件统一沉淀为 `MomoUiKit.kt`。四个页面保持持久的底栏导航。

## Cortex 真实核验状态

`CortexAuthHealthStore` **不存凭证**，只持久化上次检查结果、时间和 HTTP 状态码。加密 Token 与只读验证状态独立：

- 未保存 Token：尚未配置
- 已存但从未检查：已保存 · 尚未核验（包括旧版本迁移）
- 只读接口返回成功：上次只读验证成功（不是实时授权，也不是后台写回）
- 401/403：访问被拒绝（不擅自声称 Token 一定过期）
- 429：请求受限
- 网络错误：连接检查失败，凭证状态未知

新的候选 Bearer / Legacy 交换仅在读检查点成功后写入；失败不会覆盖已有加密凭证。清除凭证或更换开放 API Token 时递增请求代号、取消旧请求的 UI 回写，避免「清除了，又被旧请求保存回来」。后台请求只发送只读 GET 或显式 Legacy 交换，**仍没有启用不完整的上传协议**。

## 验收边界

GitHub CI 会执行 Cortex 断言、Android `:app:assembleDebug`、`:app:testDebugUnitTest`，并生成 `MomoFlow-v0.6.0-debug-apk`。**CI 不是安卓手机 UI/账号真机验收。**

真机重点：Android 17 状态栏、底栏是否遮挡；四页切换；旧凭证迁移显示待核验；403 后返回连接页是否维持失败状态；清除授权后 UI 即刻重置；通知仍可运行、只读核验成功后事务正常收尾。禁止拿真实 Token 写入截图、日志或仓库。
