# MomoFlow v0.5.4：官方同词反馈验证（尚未实现自动回写）

## 现阶段的边界

- **没有可用的官方记忆反馈写入 API**。墨墨官方开放 API 的 `study` 资源仅包含读进度、读今日列表、读学习记录、添加单词到计划、提前复习。
- 通知中的「认识·验证 / 模糊·验证 / 忘记·验证」仅代表**由用户主动开启官方同词人工验证**。点击后 MomoFlow 先读取该词官方基线，再打开墨墨原 App；用户必须手动反馈。不会自动提交“认识/模糊/忘记”到墨墨。
- 目前只有受控的**人工提交 + 官方记录对照**机制，自动点击墨墨按钮尚未实现，因为必须先验证实际 App 页面、单词一致性和界面可访问性。
- 仅需官方 App 和本人正常账号。不拦截/重放未公开接口，不注入、不修改墨墨数据文件。

## 人工对照流程

1. 在墨墨原 App **开启自动同步，并完成今日初始化**。MomoFlow 粘贴本人开放 API Token，点击同步今日真实单词。
2. 可以在 MomoFlow 的“墨墨真实回写 · 验证模式”选择单词，或在主动开启背词会话后点击通知里的「认识·验证 / 模糊·验证 / 忘记·验证」。通知动作仅在**当日、活动会话、当前单词 ID 一致**时有效。
3. MomoFlow 先对该词调用**只读** `POST /study/query_study_records`，保存 `last_response / study_count / last_study_date / next_study_date` 基线。
4. MomoFlow 打开官方墨墨。用户必须确认官方 App 显示**同一个英文词**；只有同词时才手动点击刚才选择的“认识/模糊/忘记”。否则退出，不要乱点。
5. 返回 MomoFlow，点“验证官方记录”。它会再调用同一个官方只读接口比较：
   - 记录完全相同：标记“未检测到变化”，不认定成功。若服务同步有延迟，可以稍后再查。
   - 记录有变化且最近反馈为预期：显示“检测到官方记录变化”，但不推断一定由此次操作造成。
   - 记录有变化但反馈不一致：显示“不一致”，不算成功。
   - API 错误 / 授权失效：不认定成功，保留待验证记录供再次检查。
6. 如有需要点击“取消本次验证”，不会更改墨墨记忆记录。

**注意**：`last_response` 表示官方可读取的最近反馈，`study_count` 计数和复习日期不一定每次都变化。官方服务可能延迟同步，因此“没有变化”不等于操作一定失败。即使检测到变化，也只能证明服务器记录变化，不能直接证明 MomoFlow 实现了自动回写。

## 可选：墨墨页面控件只读识别

- Android 设置 → 无障碍，**用户手动选择启用**“墨墨页面只读诊断”，才能读取页面结构。
- 在 MomoFlow 选择“只读识别墨墨背词页面控件（2 分钟）”，自动打开墨墨；返回后读取简要报告。
- 只监听 `com.maimemo.android.momo` 包名，只处理用户明确授权后的 2 分钟内的事件；仅记录目标单词是否出现、是否有**恰好**“认识 / 模糊 / 忘记”的按钮及它们是否可点击。
- **不采集其他页面文本、不导出账号/Token/屏幕内容、不执行点击。** 这只是为后续精准交互适配做准备。用户可随时在系统设置关闭服务。
- 即便控件报告可识别，也**尚不能判定自动提交可靠**；真正的程序化回写仍须建立“当前词身份一致 → 单次显式用户操作 → 精确控件目标 → 提交结果回读”的原子验证流程。

## 为什么不直接让流体云点击“忘记”回写

当前无法保证 ColorOS 原生流体云显示操作按钮；普通通知的三个按钮向本 App 发 `PendingIntent.getActivity`，只能启动验证流程，本身不拥有修改另一个 App 的记忆记录的能力。官方安卓无障碍服务支持控件操作，但可能受墨墨版本、前台状态和无障碍节点结构影响。
